Moss Launcher (Prism-based) / verification completed 2026-10-03

Built from Prism Launcher 11.1.1 (7d2d3c1ec6fcf8255ebacd02d9f792688575dfb4).
Windows x64 Release EXE and portable runtime installed in a separate directory.
Old Python Moss and existing Prism data were not imported or modified.

Automated checks
- CTest: 23 test executables passed, 0 failed (auth-preview run, 1.20 seconds).
- Windows symbolic-link cases: 7 functions skipped by default in FileSystem.
  These upstream tests can repeatedly invoke the administrator helper. They
  were not verified with elevation and were not re-run after the user's request.
  The ordinary file/path and hard-link cases remain in the FileSystem suite.
- Moss fork static invariants: 7 tests passed.
- Added offline OAuth tests: loopback-only binding, stable localhost redirect,
  public client ID in the authorization URL, PKCE S256, non-empty state,
  no exposed verifier/client secret, and rejection of a mismatched state.
  These tests do not open a browser or contact Microsoft/Minecraft.
- Java environment test: quoted JAVA_HOME, empty environment, explicit paths
  and quoted Windows PATH entries passed.
- Windows PowerShell 5's ANSI interpretation of a BOM-less UTF-8 script was
  also corrected using ASCII Unicode escapes for the Ninja include prefix.
  The fresh MossOAuth test object records 300 dependencies (not zero).
  Older objects without dependency records require a clean rebuild if their
  included headers change; this incremental build is not claimed to fix all
  existing cached object dependency records.

Interactive checks using computer-use, with a separate work/moss-prism-qa
data directory, NOT the release's UserData and NOT real Prism account data:
- Moss main window opened, with Japanese upstream UI and independent branding.
- Settings and Java settings opened.
- Java discovery completed: 9 candidates including Java 8, 17, 21, 25 and 26.
- Java 26.0.1 from C:/Program Files/Java/jdk-26.0.1/bin/javaw.exe was selectable
  from the detected list. Game launch using Java 26 has not been verified.

DLL/UAC incident and fix
- Upstream FileSystem symbolic-link tests requested administrator access many
  times. The elevated filelink helper could not locate Qt6Core/Qt6Network
  from the test process's PATH. This caused the user's error dialogs.
- Those tests are now opt-in and no longer prompt during ordinary test runs.
- Qt DLLs are deployed next to native test/helper executables, not merely in PATH.
- Portable release includes Qt6Core.dll, Qt6Network.dll, the required Qt modules
  and plugins, and unmodified Microsoft release CRT DLLs next to both EXEs.
- The privileged helper itself was not re-executed after the user requested
  that no more UAC dialogs be raised. Do not claim privileged linking is verified.

Remaining limitations
- Microsoft client ID supplied by the app owner is embedded in the auth preview:
  191f8f9d-bc7c-4f13-8989-ad109a11bf9a (public identifier, not a secret).
  Azure redirect configuration and Minecraft API approval are not confirmed.
  Authentication setup is described in MICROSOFT-SETUP.txt.
  CurseForge/Imgur still require own credentials. Prism credentials are not copied.
- The new EXE is installed in outputs/MossPrism-Windows-11.1.1-auth-preview,
  leaving the original running release and its UserData unchanged.
- The browser callback page only acknowledges a Microsoft authorization response;
  it does not claim Minecraft authentication/ownership checks have completed.
- Token persistence remains upstream JSON, not Windows-protected storage yet.
- No real-account login, Minecraft game launch, Forge/Fabric game startup,
  MOD download/update or instance migration was end-to-end verified in this run.
  The implementation is retained from upstream; this is not a claim that every
  inherited feature was tested or that all online services are ready to use.
- Visual appearance can differ with OS, Qt version, theme and translations.

The release must be kept as a whole directory. Do not redistribute UserData
containing account tokens or private keys. Corresponding launcher source,
dependency source and notices accompany the runtime package.
